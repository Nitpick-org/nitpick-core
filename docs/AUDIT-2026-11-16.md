# Audit of the base — 16 November 2026

> Static review + script execution + verification of the official LauzHack sources.
> Goal: a **healthy, runnable and LauzHack-specific** base, not a generic template.

## Verdict

The base was **good on method** (roles, deep modules, tickets, agents, rituals)
but **not runnable**: no git repository, non-executable scripts, `check.sh` and CI that
passed without checking anything, no stack, no deployment, and no LauzHack information
(schedule, jury, submission, rules). As it stood, it gave a false sense
of safety.

After the fixes: the method is kept, the blocking bugs are fixed, the LauzHack
facts are integrated, and the base is ready to receive the stack.

## P0 — blocking (fixed)

| # | Finding | Evidence | Fix |
| --- | --- | --- | --- |
| 1 | No git repository | `git status` → `not a git repository` | `git init -b main`; initial commit still to do |
| 2 | Scripts and hook not executable | `ls -l` → `-rw-r--r--`; `./scripts/check.sh` → `Permission denied` | `chmod +x scripts/*.sh .githooks/pre-commit` |
| 3 | `check.sh` fails outside git and passes with no stack | `bash scripts/check.sh` → `fatal: not a git repository`; with `package.json` absent → exit 0 | Rewritten: requires git + `package.json`, requires `typecheck`/`lint`/`test`, supports `--demo` |
| 4 | CI green without testing anything | `check.sh` exit 0 without a stack | CI requires `package.json`, runs `doctor.sh` + `check.sh` + e2e if present |
| 5 | No stack, no deployment, no e2e | no `package.json`, no deploy config | `docs/STACK.md`: decision, script contract, bootstrap, deploy, resilience |
| 6 | No LauzHack info | generic checklist | `docs/LAUZHACK.md`: schedule, venue, rules, jury, submission, logistics, sources |
| 7 | Outdated skill names | README/playbook: `/to-prd`, `/to-issues` | Replaced by `/to-spec`, `/to-tickets`; added `/setup-matt-pocock-skills` and `/grill-with-docs` |
| 8 | `progress.txt` edited by all agents | playbook + agents | `progress/<ticket>.md` per agent; `progress.txt` reserved for H2 |
| 9 | Agents with no limits or protection | no `maxTurns`, no cost, no docs guardrail | `maxTurns`, `--max-budget-usd`, `Stop` hook, `PreToolUse` hook, deny `.env` |
| 10 | `implementer` with `isolation: worktree` | double worktree if already in a worktree | Removed; the worktree is created by `new-worktree.sh` |

## P2 — improvements (left to the team)

- **Stack**: still to choose (D-4). That is deliberate: the base is agnostic.
- **Deployment**: to do on D-4. No host is imposed.
- **`docs/`**: many documents; the README map and the reading order in
  `CLAUDE.md` prevent scattering. Do not add without removing.
- **License**: unnecessary for a hackathon; the IP is yours (LauzHack rules).
- **Agent teams**: not enabled, deliberately (experimental, costly, no worktree
  isolation).
- **Persistent agent memory**: not enabled; `progress/<ticket>.md` and the docs
  are enough for 24 h.

## What was fixed

- `scripts/check.sh`: real failure without a stack, mandatory scripts, `--demo`.
- `.githooks/pre-commit`: executable, blocks `.env`, warns on `main`.

- `scripts/ralph-once.sh` / `afk-ralph.sh`: `--max-budget-usd`, `--permission-prompts none`,

  limits.

- `CLAUDE.md`: project state, agent contract, shared files, DoD, prohibitions.
- `README.md`, `AGENTS.md`, `PLAYBOOK.md`, `PRE-EVENT-CHECKLIST.md`, `PRD.md`, `DEMO.md`,
